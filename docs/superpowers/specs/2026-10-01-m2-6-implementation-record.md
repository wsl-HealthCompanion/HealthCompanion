# M2.6 — 同屏练习与反馈延迟实施记录

日期：2026-10-01。分支：feat/pose-shoulder-loop。状态：界面和发送流程开发完成，真人验收待用户操作。

## 本轮改动

- 摄像头和数字人放在同一练习行；姿势角度、计时和诊断区域移到下方。宽屏并排，小屏为可读的纵向布局。
- 把反馈时间拆成两段：姿态稳定/完成事件 → Xmov SDK 收到本地 `speak` 调用；SDK 调用 → SDK 首次语音状态 `start` 回调。面板显示两段秒数。
- 时间使用浏览器 `performance.now()`；不发送日志、帧、关键点或数字人凭据到新增服务。
- 有证据的本地等待问题：Bridge 原先把整个 `provider.speakFeedback()` Promise 纳入发送队列；若 SDK Promise 在语音结束才兑现，后续稳定事件要等上一段语音。队列现只等待必要的打断和 SDK 调用发出，语音完成由独立回调处理并显示错误。未经证实的 Xmov 服务端/TTS 延迟不在本轮臆测。
- 第二段计时是 SDK 首次语音状态回调，不是声卡或用户听到第一声音的物理测量；SDK 若缺少回调则不会显示第二段时长。
