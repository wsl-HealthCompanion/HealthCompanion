# M2.3 动作会话与保持计时实施记录

日期：2026-10-01。分支：`feat/pose-shoulder-loop`。

## 目标与验证范围

本阶段沿用 M2 的既定设计，将 M2.2 的逐帧 PoseAssessment 转换为稳定反馈和一次动作完成结果。

用户明确选择「先完成开发，暂不自动测试」。因此本阶段不新增测试文件、不运行自动测试，也不沿用 M2.2 的测试数量作为 M2.3 验收结果。编译、生产构建和静态审查不等于计时行为已经通过自动或真人验收。

## 新增接口

- `PoseSessionController(config?)`：接收可选配置，默认分类稳定时间 500 ms、正确保持时间 3000 ms、最大新样本间隔 250 ms。
- `start(nowMs)`：开始会话；活动或暂停中的重复 start 不重置会话；完成后显式 start 可开启新会话。
- `update(assessment, nowMs)`：仅接收一次新的推理结果，返回 `{ snapshot, events }`。
- `tick(nowMs)`：让界面定期检查样本是否过期；不增加保持进度，不生成完成事件。
- `pause()` / `resume(nowMs)`：暂停并清零计时，恢复后重新稳定判断。
- `stop()`：返回 idle，清空测量、计时和源帧水位。
- `getSnapshot()`：返回独立副本，含 status、最新 assessment、stableIssues、holdMs、holdTargetMs。

控制器没有内部定时器。nowMs 来自同一个单调时钟，例如 `performance.now()`，必须为有限非负值；活动会话中的 update/tick/resume 时间倒退会报错且不修改状态。

## 状态与保持行为

| 情况 | 实现行为 |
| --- | --- |
| 开始会话 | acquiring，等待稳定分类 |
| 姿势问题连续稳定 500 ms | coaching，发出一次对应反馈 |
| 同一组问题持续存在 | 更新测量，不逐帧重复发事件 |
| 正确姿势连续稳定 500 ms | holding，发出 pose_correct，从 0 ms 开始保持 |
| 连续正确保持 3000 ms | completed，发出一次 completed |
| 保持中出现一个新无效样本 | 立即清零，不等错误分类稳定 500 ms |
| 再次回到正确姿势 | 重新稳定 500 ms，再从 0 保持 3000 ms |
| 完成后继续输入样本 | 保持终态，不重复发完成事件 |
| 暂停、停止或恢复 | 不继承旧保持时间 |

分类身份取完整、有序的问题集合；角度在同一规则分类中波动不会重复触发反馈。事件优先级为人体不可用 → 镜头范围 → 其他姿势反馈。

## 时钟与新样本约定

媒体时间和观察时间分开使用：

- `assessment.measurement.timestampMs`：源帧的时间戳，只作为新帧水位；重复或倒序的有限源时间戳被忽略，不推进稳定/保持时间。
- `nowMs`：本次新推理结果被消费时的单调观察时间；500/3000 ms 用这个时钟计算。
- 没有检测到人体时，源时间戳可以为 null；仍能形成 body_not_visible 分类。
- 新样本间隔超过 250 ms 时，清空稳定分类和保持时间，回到 acquiring；下一帧需要重新稳定。间隔正好等于上限仍有效。
- `tick()` 和过期检查保留源帧水位，旧缓存帧不能在过期后被重新当作新帧。
- 暂停/恢复保留水位；如果摄像头或其媒体时钟重开，调用 stop/start 开启新会话。

250 ms 是为当前 10–15 Hz 推理目标设置的可配置连续性上限，不是实机测量结果；后续应根据目标机器调节。调用方必须按新推理结果调用 update，不能自行给缓存结果伪造递增时间戳。

## PerceptionEvent

事件名：body_not_visible、framing_issue、exercise_feedback、pose_correct、completed。

字段：source=pose、单调观察 timestampMs、payload.exercise=shoulder_raise，以及有限的左右臂角度、躯干倾斜、镜头范围、问题列表和 holdMs。不可用的角度省略；没有可靠聚合置信度时省略 confidence。

事件映射逐个复制允许的字段，不附带原始关键点、图像、视频或完整 assessment 对象。输入、快照和事件数组彼此独立，避免调用方修改快照后污染会话。

## M2.4 接入说明

1. 用户点击开始训练时调用 start；摄像头继续采用明确的用户授权启动。
2. 每次新的 PoseProbeSample 用 M2.2 assessShoulderRaise 生成 assessment，并用单调观察时间调用 update。
3. Widget 显示 snapshot 的实时角度、问题、状态和 holdMs / holdTargetMs；消费本次返回的 events 一次，不回放历史事件。
4. 界面定期调用 tick，使推理停止时及时清零过期的保持状态；界面刷新不能推进保持计时。
5. 摄像头停止、会话停止或页面卸载调用 stop；推理错误可 pause，恢复后需重新稳定。取消界面刷新调度仍由页面负责。
6. M2.5 再从稳定事件触发固定播报和已验证的 Xmov 动作；M3 再封装为 Agent 工具。

当前 Pose Lab 页面保持探测用途，本阶段没有接入训练控件或实时反馈。
