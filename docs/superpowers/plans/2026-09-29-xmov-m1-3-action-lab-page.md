# Xmov Milestone 1.3 Action Lab Read-Only Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 H5 中新增独立的 `/xmov-action-lab.html` 开发页，读取 M1.2 的稳定接口并展示真实 KA 动作总数、semantic、中英文名称和类型。

**Architecture:** H5 新增一个轻量 API client 消费 `GET /api/v1/xmov/actions`，页面组件只处理 loading / ready / empty / error 四种展示状态；独立 HTML 入口不修改 `App.tsx` 和主聊天链路。为保证独立页面能够进入生产构建，Vite build 明确注册 `index.html`、`xmov-task1.html` 和 `xmov-action-lab.html` 三个入口。

**Tech Stack:** React 18, TypeScript 5.3, Vite 5, Vitest 2.1.9, ReactDOM Server for pure view tests.

**Spec:** `docs/superpowers/specs/2026-09-29-xmov-action-lab-design.md`

## Global Constraints

- 只实现 M1.3：真实动作列表的只读 Action Lab。
- 数据源固定为 M1.2：`GET /api/v1/xmov/actions`。
- 浏览器 client 使用现有 `API_BASE`，默认请求 `${API_BASE}/xmov/actions`。
- 后端正常浏览器响应由全局 ResponseInterceptor 包装，因此 canonical payload 为 `{ code, message, data: { actions }, requestId }`。
- H5 client 同时接受直接 `{ actions }`，仅用于保持本地/测试调用兼容；两种形态都必须要求 `actions` 是数组。
- 页面展示：加载状态、动作总数、semantic、英文名、中文名、类型、空列表状态、API 错误状态。
- M1.3 不显示 `imageUrl/movieUrl` 预览；预览属于 M1.4。
- M1.3 不加载 `XmovAvatarProvider`、不试播动作、不创建 Action Registry。
- 不修改 `App.tsx`、主 `index.html` 页面内容、聊天链路或 LiveTalking fallback。
- 不把真实 Xmov 凭据放进前端源文件。
- H5 当前使用 Vite 5，因此测试依赖固定为 `vitest@2.1.9`；不升级 Vite 主版本。
- `npm run build` 后必须同时存在 `dist/index.html`、`dist/xmov-task1.html`、`dist/xmov-action-lab.html`。

## Review Focus

1. **全局响应包装**：实际 NestJS 返回 `data.actions`，client 必须正确取出，不能只在直接调用 Controller 时工作。
2. **HTTP 成功但 payload 异常**：缺少 `actions` 或 `actions` 非数组必须进入 error，不得显示成“0 条”。
3. **空列表与失败不可混淆**：真实 `actions: []` 显示“0 条/暂无动作”，请求失败显示错误。
4. **页面与主应用隔离**：Action Lab 入口不能 import `App.tsx`，也不能改变主聊天状态。
5. **生产多页构建**：不能只在 Vite dev server 可访问；build 后 Action Lab HTML 必须真实生成。
